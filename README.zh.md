## 快速开始

没有任何依赖，也不需要安装任何东西。

### 方式一：直接打开

双击 `index.html` 即可开始游戏。

### 方式二：本地静态服务器（推荐）

`localStorage` 与 Gamepad API 在 `file://` 协议下可能被浏览器限制，用任意静态服务器托管更稳定：

```bash
# Python
python -m http.server 8080

# 或 Node.js
npx serve .
```

然后访问 <http://localhost:8080>。

### 环境要求

任何支持 Canvas 2D、Gamepad API 与 WebAudio 的近期版本浏览器（Chrome / Edge / Firefox / Safari）。推荐使用 Chrome 或 Edge 以获得完整手柄支持。

## 特性

### 竞速与玩法

- **伪 3D 分段投影引擎** —— 沿 Z 轴把赛道切分为段，逐段透视投影，支持坡道起伏、弯道离心力、远处雾效与地平线遮挡裁剪。
- **12 车手网格发车** —— 11 台 AI + 玩家，玩家从末位发车一路追赶。
- **漂移蓄力涡轮** —— 漂移蓄满 1.0s 触发迷你涡轮，2.2s 触发超级涡轮，蓄力阶段与颜色分级实时可读。
- **道具混战** —— 7 种道具，按名次加权抽取的道具轮盘：落后者更容易拿到闪电／星星这类翻盘道具。
- **有性格的 AI** —— 11 位具名车手各有 pace（节奏）／caution（谨慎度）／lane（偏好车道）／itemDelay（道具延迟）参数。AI 会前瞻前方弯道提前减速，并在三车道中选择最优线路躲避路障与对手。
- **橡皮筋平衡** —— AI 落后加速、领先收敛，保持整局比赛的紧张感。
- **赛道专属规则** —— 冰峰滑道抓地力更低，入弯要更早；火山狂飙的热风区会周期性推挤车身。
- **赛道障碍** —— 锥桶、油渍（打滑）、泥地（持续减速）、轮胎、木桶，各赛道配置不同。
- **单圈纪录本地保存** —— 每条赛道的最佳单圈写入 localStorage，选赛道页直接展示。

### 呈现与体验

- **全部素材程序化生成** —— 树木、棕榈、仙人掌、雪人、建筑、霓虹灯、龟壳、香蕉全部由 Canvas 路径绘制；引擎声与提示音由 WebAudio 振荡器实时合成。**仓库内不含任何图片／音频／字体文件。**
- **8 条风格化赛道**，难度从 1 星到 5 星，配色主题、背景样式、装饰精灵各不相同。
- **键盘与手柄无缝热切换** —— 统一输入层每帧轮询合并，游戏中插上或拔掉手柄立即生效并给出提示，无需重启或改设置。
- **后视摄像机** —— 按住 `Q` / `RB` 回望身后对手。
- **完整 HUD** —— 圈数、名次、总时间、最佳单圈、时速表、道具槽（含轮盘滚动动画）、漂移蓄力条、小地图、事件提示。
- **响应式布局** —— 窗口宽度小于 700px 时自动切换紧凑布局，适配小窗口。
- **11 种界面语言** —— 支持简体中文、繁体中文、英语、法语、西班牙语、葡萄牙语、意大利语、日语、韩语、拉丁语与希腊语，标题页切换后自动保存选择。
- **完整设置界面** —— 标题页可进入设置，调整语言、50%／75%／100% 渲染分辨率、30／60／120／无限制帧率，并重绑九项驾驶按键。
- **统一字标** —— `HORIZON RACE` 使用高挑衬线造型、金色副标题和横线托底，不随界面语言变化。
- **暂停与失焦保护** —— `P` / Start 暂停；窗口失焦自动暂停并清空按键，切回来不会油门卡死。
- **音频自动解锁** —— 首次按键／点击时初始化 AudioContext，符合浏览器自动播放策略。

## 道具

道具箱成排横跨路面，拾取后进入约 1 秒的轮盘滚动再揭晓。抽取概率按当前名次加权：领跑者偏向香蕉／绿龟壳这类防守道具，落后者更容易拿到星星／闪电这类翻盘道具。

| 道具 | 效果 |
| --- | --- |
| 加速蘑菇 | 短时提速，可突破常规速度上限 |
| 三重蘑菇 | 储存 3 次，连续使用 |
| 香蕉皮 | 向车后投掷，后方车辆碾过原地打转 |
| 绿龟壳 | 直线向前飞行，撞击首个命中的对手 |
| 红龟壳 | 锁定前方最近目标并持续追踪其横向位置 |
| 无敌星星 | 约 5 秒免疫碰撞、撞飞对手并小幅提速 |
| 闪电 | 全场其他车手失控打转并大幅减速 |

> 龟壳与香蕉对投放者本人有短暂的免伤宽限期；道具槽已满时不会消耗道具箱。

## 实现要点

### 伪 3D 投影

赛道被切成 `SEG_LEN = 200` 单位一段的分段路面，每段记录起终点世界坐标与曲率。渲染时把分段变换到摄像机空间，用 `scale = camDepth / camera.z` 得到屏幕坐标与路宽，从远到近以梯形多边形逐段绘制 —— 由此得到弯道、坡道与远景雾化效果。

`DRAW_DIST = 300` 段为可视深度，`FOG_DENSITY` 控制远处淡入雾色的速度。车辆、龟壳、香蕉不做整段显隐，而是按各自深度连续投影，因此坡后物体会被地平线正确遮挡，而不是穿模提前出现。摄像机位于玩家车辆后方，前方物体经过车辆后会继续沿赛道移向画面底部，越过摄像机后才消失。

### 赛道描述与构建

`js/tracks.js` 只存放数据，`buildTrack()` 负责解释指令：

```js
["s",  len]              // 直道
["c",  len, curve]       // 弯道（正=右弯，负=左弯）
["h",  len, dy]          // 坡道
["ch", len, curve, dy]   // 复合弯坡
["sc", len, k]           // S 型连续弯
```

入弯与出弯用 easeIn / easeInOut 缓动过渡；坡度拼装完成后自动补一段回程坡道，使起终点闭合。小地图路径由曲率积分得到，并抵消积分累计误差以闭合成环。

### 模块划分

按职责拆分，保持 `<script>` 顺序加载（无模块打包器）：

```
tracks.js -> i18n.js -> settings.js -> input.js -> game.js -> race.js -> ai.js -> render.js -> ui.js -> main.js
```

`i18n.js` 管理语言、赛道名、规则、道具名和界面文案；`settings.js` 管理分辨率、帧率和键位偏好；`game.js` 集中调参、工具函数、音效、赛道构建和共享状态；`race.js` 负责比赛初始化、道具、状态效果与玩家物理；`ai.js` 负责世界更新（AI 决策、弹道、香蕉、卡丁车碰撞推挤）；`render.js` 负责投影、程序化精灵、背景、赛道与 HUD；`ui.js` 负责标题／设置／选赛道／暂停／倒计时／结算界面；`main.js` 是状态机主循环。

## 项目结构

```
.
|-- index.html        # 页面外壳：全屏 canvas + 脚本引用
`-- js/
    |-- tracks.js     # 8 条赛道的数据定义（纯数据，无逻辑）
    |-- i18n.js       # 11 种语言的界面文案、赛道与道具名称、本地偏好

    |-- input.js      # 可重绑键盘 + Gamepad 每帧合并、边缘检测
    |-- game.js       # 集中调参／工具／音效／赛道构建／共享状态
    |-- race.js       # 比赛初始化／道具／状态效果／玩家物理
    |-- ai.js         # 世界更新：AI 决策、龟壳与香蕉弹道、车辆碰撞
    |-- render.js     # 投影／程序化精灵／背景／赛道渲染／HUD／小地图
    |-- ui.js         # 标题、选赛道、倒计时、结算界面
    `-- main.js       # 状态机与 requestAnimationFrame 主循环
```

约 2,620 行 JavaScript，零第三方依赖。

## 开发说明

- **无需构建** —— 改完代码刷新浏览器即可。
- **集中调参**：速度、加减速、漂移阈值、AI 橡皮筋与预判、雪地抓地力、火山热风强度都在 `js/game.js` 顶部的 `GAME_TUNING`；单个 AI 的 pace / caution / lane / itemDelay 在 `DRIVER_PROFILES`。
- **画面参数**：近景精灵尺寸上限和坡道裁剪在 `js/render.js`；紧凑布局阈值与界面排版在 `js/render.js`、`js/ui.js`。
- **新增赛道**只需在 `TRACKS` 里追加一项数据（`id` / `name` / `theme` / `ops` 等），构建器与选赛道界面会自动接上。
- 最佳单圈键名为 `hr_best_<trackId>`，清空站点数据即可重置。
- 语言偏好键名为 `hr_language`；新增界面文案时，需要为 `js/i18n.js` 中的 11 种语言同时补齐对应项。
- 图形、帧率和键位配置保存在 `hr_settings`；分辨率选项控制 Canvas 内部渲染尺寸，CSS 仍保持全窗口显示。

### 无构建交付检查

项目没有编译步骤。修改后可以用 Node.js 检查所有脚本是否能解析：

```powershell
Get-ChildItem js -Filter *.js | ForEach-Object { node --check $_.FullName }
```

`index.html` 中的脚本顺序属于运行依赖，不应随意调整。新增脚本时同时更新上面的模块链和页面引用。

### 提交范围说明

仓库只包含运行游戏所需的文件。开发过程中的**个人工程文件**（迭代计划、本地测试脚本）已由 `.gitignore` 排除，不会进入版本库，也不影响他人 clone 后直接游玩。
